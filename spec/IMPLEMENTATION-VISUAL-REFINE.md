### 3.8 一般化教训（本轮新增两条，建议入项目纪律）

1. **证据口径必须与「谁看的」绑定。** 本项目已有「动画有没有播只能靠时间点截帧证明」的纪律，本轮再进一步：
   **截帧不等于目视**。在模型侧读图不可用的环境里，判据只能来自可复现的数值（世界盒 / 屏幕投影 / 像素采样），
   截图是**留证**而非**证据来源**。报告里凡写「看着像 / 实拍可见」都是**无源断言**，必须改成「实测 X = Y ≥ 阈值」。
   → 建议把「判据来源必须可复现」写进下一轮规格的验收条款。
2. **几何解算要反向验一遍单调性**（同 E5 分层判据的教训在这里复现）：
   浇包悬停解算的符号错误 `−y·sinθ` 表面上「能跑」，但偏距随倾角**递增**，与「满倾时内收」的物理直觉**反向**。
   凡是「随参数变化的偏移量」，落代码前先手算两个端点（θ=0 与 θ=max）看方向对不对。
3. **规格自相矛盾的识别优先于实现**：Q3.4「挪包」与「相机四预设不动」两条同时成立时，P1 物理不可达 ——
   这与 E5 ②③「唯一暖源在墙背面 + 墙面要亮到 140」是**同一类错误**（要求的观测条件与允许的手段互斥）。
   识别方法是**先做可行性反推**：把判据需要的视线/光照条件代入几何，能在写代码前就发现问题。
