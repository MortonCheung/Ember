## 2. 技术栈（已定，不要替换）

### 6.4 三维空间（Step 1 核心）

**Step 1 只要一个"空车间盒子"**，用来验证渲染管线、控制器、性能。

| 项目 | 规格 |
|---|---|
| 场景尺寸 | 车间空间 `40m(宽) × 30m(高) × 60m(深)`（贴近真实铸造馆尺度） |
| 地面 | `PlaneGeometry`，`MeshStandardMaterial`，`#2A2F36`，`roughness 0.9` |
| 墙面 | 三面（后/左/右）用 `BoxGeometry` 薄片模拟，`#23282F` |
| 屋架 | 横梁 + 斜拉杆（`BoxGeometry`），合并为单 mesh，`#3A4149` |
| 中柱 | **4 根**圆柱（`CylinderGeometry`，半径 `0.55/0.7`），`#525D69`，位置 **(±13, 6)** 和 **(±13, −18)** |
| 关键道具 | **冲天炉占位体**：`CylinderGeometry(2.0, 2.4, 12)`，`#3A4149`，位于 `(-6, 0, -8)`；炉口一圈 `#E8663C` 发光环（`TorusGeometry`）+ 加料平台 `BoxGeometry(6, 0.25, 3.4)` 于 `y = 8.4` |
| 网格辅助 | **不要开 `GridHelper`**（太像编辑器，不像展馆） |
| 地面导向线 | 2 条 `#E8663C` 半透明细长面片，沿作业通道走向，`opacity 0.18` |
| 相机 | `PerspectiveCamera`，`fov 55`，初始位置 `(16, 10, 23)`，看向 `(-3, 6.5, -5)`（对准冲天炉，让主角居中） |
| 阴影 | `PCFSoftShadowMap`，`shadow.mapSize 1024`（Step 1 别上 2048） |
| 雾效 | `FogExp2`，颜色 `#0E1116`，密度 `0.012` —— 让远处墙面自然淡出，掩盖几何简陋 |
| 渲染器 | `antialias: true`，`powerPreference: "high-performance"`，`setPixelRatio(Math.min(devicePixelRatio, 2))` |

**构图约束（实测踩过的坑，务必遵守）**：
- ⚠️ **立柱必须避开镜头视线走廊**。相机在 `(16,10,23)` 看向 `(-3,6.5,-5)`，若立柱放在 `z = ±14.4` 附近会有一根正好挡在画面中央、遮住冲天炉。**按上表的 (±13, 6) / (±13, −18) 放**。
- ⚠️ **初始视角不能太暗**。Step 1 的场景是"熄火后的车间"，但不能黑到看不清主体。按下表灯光参数，确保冲天炉是画面里唯一有暖光的物体。

**灯光参数（实测调优后的值，按此实现）**：

| 光源 | 参数 |
|---|---|
| `HemisphereLight` | 天 `#8FA3B8` / 地 `#1A1E24`，强度 **0.75** |
| `DirectionalLight`（主光，带阴影） | 暖白 `#FFE8D6`，强度 **1.15**，位置 `(16, 26, 14)`；`shadow.camera` 范围 ±34，`bias -0.0006` |
| `PointLight` × 2（炉火） | `#E8663C`，强度 **2.4**，`distance 30`，`decay 1.4`，位置 `(-6±1.5, 11.2, -8)` |
| `PointLight`（炉底补光） | `#FFB08A`，强度 **0.9**，`distance 22`，位置 `(-6, 4, -2)` |

**炉火微动**：两个炉火点光做呼吸动画，让静止场景"活着"：

```js
// 低频呼吸 + 高频抖动，模拟炉火不稳
const phase = t * 0.0016 + i * 1.7;
light.intensity = base * (0.86 + Math.sin(phase) * 0.1 + Math.sin(phase * 4.3) * 0.04);
```

同时炉口环的亮度同步轻微起伏（`setHSL` 的 lightness 在 0.50–0.60 之间）。

### 6.5 控制器（Step 1 必须能用）

## 7. 降级策略（B 档硬要求）

`fallback.js` 必须实现：

```js
// 检测顺序
1. WebGL2 可用？ → 用 WebGL2Renderer 路径
2. 不可用但 WebGL1 可用？ → 降级到 WebGL1，关阴影、关雾
3. 全不可用 → 渲染「降级页」：
   - 全屏 var(--c-bg)
   - 居中卡片：标题「当前浏览器不支持三维预览」+
     正文「建议使用最新版 Chrome / Edge / Safari 访问」+
     一行小字说明「本页面的展陈内容与交互逻辑在三维模式下完整呈现」
   - 卡片下方仍然提供「浏览图文版展厅」按钮（Step 1 可只做占位）
```

另需：**加载中状态** —— three.js 初始化期间，视口中央显示一个 `--c-iron` 色的环形加载指示（纯 CSS 动画），超时 8s 未完成则显示降级页。

## 8. 性能预算（Step 1 必须守住）

| 指标 | 预算 | 说明 |
|---|---|---|
| Draw call | ≤ 60 | Step 1 场景简单，很容易达标 |
| 三角面数 | ≤ 80k | 空盒子场景实际会在 1k 以内 |
| 纹理内存 | ≤ 32MB | Step 1 基本无纹理 |
| 首包 JS（gzip） | ≤ 400KB | three.js 核心约 150KB gzip，留余量 |
| 帧率 | ≥ 55 FPS 空闲态 | 见 A5 |

**优化动作（现在就要做，别等出问题）**：
- 所有静态几何体合并到尽量少的 mesh（`mergeGeometries` 或 `BufferGeometryUtils.mergeGeometries`）—— demo 里已示范一个极简实现，可直接用
- 用 `requestAnimationFrame` 或 `renderer.setAnimationLoop` 均可，但**必须处理可见性**：`document.hidden` 时暂停循环，切标签页不烧 GPU
- 页面卸载 / 路由切换时释放资源：`geometry.dispose()`、`material.dispose()`、`controls.dispose()`、`renderer.dispose()`
