## 1. 总览

互动体验有两条支线，对应画稿 S03 / S04：

| 支线 | 路由 | 画稿 | 玩家操作 | 产出 |
|---|---|---|---|---|
| **亲手浇铸** | `#/cast` | S03 | 选砂箱 → 定铁水温度 → 调浇注速度与砂型湿度 → 浇注 | 浇铸评分（0–100）+ 病因诊断 + 解锁馆藏 |
| **协作车削** | `#/turn` | S04 | 双人分别控制主轴转速 / 进给量 → 车削 | 质量分 + 用时 + 团队协作分 + 排行榜 |

**共同设计原则**（这是本作品的创新点，也是最容易被做成"假交互"的地方）：

| 原则 | 含义 | 反面（不要做） |
|---|---|---|
| **确定性** | 同一组参数 → 同一分数，**零随机** | ❌ 随机分数、随机暴击 |
| **可解释** | 每一分都能说出"哪个参数、超了多少、什么机理" | ❌ 只给分数不给原因 |
| **有出处** | 规则来自真实铸造/切削工艺规律 | ❌ 为了难度瞎编数值 |
| **可预期** | 参数在哪、会怎么扣分，玩家能算出来 | ❌ 黑箱 |
| **单向后果** | 砂型一次性、参数不可撤回 | ❌ 无限重试削弱代入感 |

**导航接入**：现有导航「互动体验」→ `#/cast`（当前是占位 `#`，本次接通）。`#/turn` 从浇铸结算页进入，不进主导航。

## 2. 交互流程（浇铸）—— 5 步状态机

画稿 S03 顶栏已定 5 步：**①取样 ②调温 ③浇注 ④开箱 ⑤评分**。逐步规格如下。

### 状态机总览

```
[①取样] --选中砂箱--> [②调温] --确认温度--> [③浇注] --点击"开始浇注"--> [④开箱] --动画结束--> [⑤评分]
   ↑                                                                              |
   └──────────────────── 「另取一箱」/ 砂箱耗尽后「重新制型」 ──────────────────────┘
```

### ① 取样（Select）

- **交互**：视口内 12 只砂箱可射线拾取。命中判定用 Step 2 已实现的约定：
  `Raycaster` 命中 `InstancedMesh` → 读 `instanceId` → 查 `mesh.userData.sandboxNames[instanceId]` → `sandbox_0…sandbox_11`。
- **每只砂箱携带的静态数据**（见 §3.2）：所属**铸件类型**、**初始砂型湿度 H₀**、**难度星级**、**对应馆藏图鉴**。
  > 铸造上说得通：砂型是按某件模样造型的，所以**选定砂箱即同时定下了要浇什么铸件** —— 不需要再有"选铸件"这一步。
- **前置约束**：已浇注过的砂箱（状态 `consumed`）**不可再选**：视觉上压暗（`opacity 0.45`）、`cursor: not-allowed`、点击无响应。
- **无副作用**：射线未命中任何砂箱时，不进入下一步、不改变任何状态。
- **出口**：「进入调温」按钮在选中后激活（`--c-iron` 填充，画稿 S03 主按钮规格）。

### ② 调温（Heat）

- **交互**：单滑杆 **铁水温度 T**，范围 **1320–1520 ℃**，步长 5 ℃。
- **实时反馈**：HUD 右侧大数字显示 `T ℃`（画稿 S03：「1380 °C」+ 徽标「偏低 · 需升温」）。
  徽标逻辑：`T < 理想下限` → 「偏低 · 需升温」；`T > 理想上限` → 「偏高 · 需降温」；区间内 → 「适宜」。
- **离场提示**：`|T − 理想中值| ≥ 20 ℃` 时，视口左上浮出注解「温差过大，铸件将产生缩孔」（画稿 S03 原文）。
  > 这条注解**不分方向**（偏低/偏高都显示）：缩孔本身就是双向风险 —— 温度偏低时补缩通道提前凝固，
  > 温度偏高时液态收缩量过大。保持画稿原文，不要改成单向文案。
- **出口**：「进入浇注」。

### ③ 浇注（Pour）

- **交互**：两个滑杆 + 一个主按钮（画稿 S03 底部控制条，两个滑杆并排）：
  - **浇注速度 V**：8.0–24.0 kg/s，步长 0.5。注解「建议浇注速度 12–18 kg/s」（画稿 S03 原文，数值随铸件类型变化）。
  - **砂型湿度 H**：1.5–8.0 %，步长 0.1。**滑杆左=湿、右=干**，物理含义是"烘干程度"；
    文案标注「砂型湿度 / 烘干程度」，`H < 理想下限` → 提示「砂型过干，强度不足」。
- **不可撤回**：点击「开始浇注」后，参数锁定，滑杆置灰。
- **出口**：「开始浇注」→ 进入开箱。

### ④ 开箱（Open）

- **表现**：砂箱上半箱抬起、型砂散落（`Points` 粒子或缩放动画），铸件显现。
  铸件外观必须体现缺陷：气孔 → 表面暗色凹点；冷隔 → 顶部缺口；胀砂 → 轮廓外凸。
  > 视觉呈现可用着色器或**按缺陷数量替换预制的 3 档贴图**（推荐后者，成本可控且可复现）。
- **时长**：**2.0 s**，可点击「跳过」直接进入评分。
- **无交互**：此步不接受参数输入。

### ⑤ 评分（Score）

- **表现**：右侧面板（画稿 S03 右栏）依次揭示：主分数 `Math.round(总分)` → 三个子项条（`造型完整度 / 气孔控制 / 铁水利用率`）→ 病因诊断文案。
- **揭示动效**：分数与进度条 **600 ms** 内从 0 走到目标值，`prefers-reduced-motion` 下直接显示终值。
- **出口**：两个按钮（画稿 S03 原文）：
  - 「调整参数重试」→ 回步骤 ②，**但沿用同一只砂箱**（允许调参重来，符合"废品重浇"的现实）；
    > 注意：这与"砂型一次性"不冲突 —— 重试＝重造砂型，H₀ 不变。
  - 「存为我的工牌」→ 写入工牌数据并跳 `#/vault`（画稿 S05）。

### 状态与持久化

| 数据 | 存储 | 说明 |
|---|---|---|
| 本局参数与得分 | 内存 | 切路由即丢 |
| 已消耗砂箱列表 | `sessionStorage` | 防"刷新农场"；关闭标签页即清空 |
| 工牌数据 | `localStorage` | 画稿 S05 需要；字段见 §6 |
| 馆藏解锁进度 | `localStorage` | `3/12` 的来源 |

## 4. 评分模型（浇铸）

### 4.1 子项与权重

| 子项 | 权重 | 衡量什么 |
|---|---|---|
| **造型完整度** | **40 %** | 形状是否完整、轮廓是否清晰（冷隔 / 浇不足 / 冲砂 / 缩孔 / 胀砂） |
| **气孔控制** | **40 %** | 内部与表面气孔（湿气发气 / 卷气 / 低温增粘） |
| **铁水利用率** | **20 %** | 工艺经济性（浇注系统被迫加大 / 飞溅 / 补浇回炉） |

**总分 = 0.40 × 造型完整度 + 0.40 × 气孔控制 + 0.20 × 铁水利用率**

> **权重不是拍的**：以画稿 S03 的三项分（88 / 54 / 76）与总分 72 反解，
> 只有 40/40/20 能精确得到 72.0。也就是说这份权重是**从已出画稿里解出来的**，
> 换任何其他权重都会与已有视觉稿矛盾。见 §5 对账。

### 4.2 扣分规则矩阵（核心表）

**每个子项 = 100 减去若干条扣分。** 每条扣分只由一个参数驱动：

```
扣分 = 0                                       若 参数落在 [理想下限, 理想上限]
     = min(上限, (理想下限 − 参数) × 系数)      若 参数 < 理想下限
     = min(上限, (参数 − 理想上限) × 系数)      若 参数 > 理想上限
```

**三条实现纪律（重要，否则分数会对不上）**：

1. **每个参数在每个子项内最多只取一条**（取扣分最大的那条），避免"同一个原因扣两次"。
2. **每条扣分独立设上限**，累加后子项最低为 0（不出现负分）。
3. **内部用浮点（保留 2 位）、只在显示时 `Math.round`**；加权计算用未取整值。

| 子项 | 参数 | 触发方向 | 系数 | 上限 | 缺陷名（用于文案）| 机理 |
|---|---|---|---|---|---|---|
| 造型完整度 | T | 低于理想下限 | 0.60 /℃ | 45 | **冷隔** | 过热度不足，薄壁处先凝固；补缩通道提前凝固亦引发缩孔 |
| 造型完整度 | T | 高于理想上限 | 0.60 /℃ | 45 | **缩孔** | 液态收缩量大、凝固慢 → 缩孔与晶粒粗大 |
| 造型完整度 | V | 低于理想下限 | 2.00 /(kg/s) | 30 | **冷隔** | 充型太慢，前端降温凝固 |
| 造型完整度 | V | 高于理想上限 | 2.50 /(kg/s) | 35 | **冲砂 / 多肉** | 冲刷型壁，砂粒进入铸件 |
| 造型完整度 | H | 低于 2.5 % | 10.0 /% | 30 | **胀砂 / 掉砂** | 型砂强度不足，型壁被铁水撑开 |
| 气孔控制 | H | 高于 5.0 % | **36.0 /%** | 70 | **气孔** | 型砂水分发气，气体侵入铸件 |
| 气孔控制 | V | 高于理想上限 | 2.50 /(kg/s) | 25 | **卷气 / 夹渣** | 湍流卷入气体与氧化膜 |
| 气孔控制 | V | 低于 10 kg/s | 1.50 /(kg/s) | 20 | **氧化夹杂** | 充型过慢，表面氧化膜卷入 |
| 气孔控制 | T | 低于 1395 ℃ | 0.20 /℃ | 25 | **气孔（增粘）** | 温度低、粘度大，气泡难上浮 |
| 铁水利用率 | T | 低于理想下限 | 1.20 /℃ | 30 | **浇注系统被迫加大** | 流动性差需大截面，占用铁水 |
| 铁水利用率 | V | 高于理想上限 | 2.00 /(kg/s) | 25 | **飞溅 / 溢流** | 铁水飞溅浪费 |
| 铁水利用率 | V | 低于 10 kg/s | 2.00 /(kg/s) | 25 | **需补浇 / 回炉** | 未充满须二次补浇 |

> **为什么 T 与 V 会同时影响三个子项**：这是真实的 —— 温度低既造成冷隔（造型）、
> 又让气泡难上浮（气孔）、还逼你把浇注系统做大（利用率）。**交叉耦合正是这个模拟的价值所在**，
> 不要为了"干净"把它拆成三个独立参数。

### 4.3 病因诊断文案生成

画稿 S03 的诊断原文：

> 气孔偏高：砂型湿度 6.2% 超过 5% 上限，高温铁水遇湿气产生气孔。调整后重试可提升至 90 分以上。

**模板**：

```
{缺陷名}{偏高|偏低}：{参数名} {值}{单位} {超过|低于} {阈值}{上限|下限}，{机理}。{建议}。
```

| 字段 | 取值规则 |
|---|---|
| 缺陷名 | 全场扣分**最大**的那一条（并列时按 造型 → 气孔 → 利用率 的顺序取前者） |
| 值与单位 | `T` → 整数 +「℃」；`H` → 1 位小数 +「%」；`V` → 1 位小数 +「kg/s」 |
| 阈值 | 该条规则触发的区间端点 |
| 机理 | 取 §4.2 表最后一列 |
| 建议 | 「调整后重试可提升至 N 分以上」，N 见下 |
| **N** | 把**主因参数**修正到区间端点、其余参数不变，重算总分，然后 **向上取整到 5 的倍数** |

> 以 S03 为例：湿度修正到 5.0 后总分 = 89.2 → 取整到 **90** → 文案正好是「可提升至 90 分以上」。
> **向上取整到 5** 这条规则就是为了让这句文案成立，且它同时保证了文案永远不会把预期说低。

**无任何扣分时**（三项全 100）的文案：`工艺参数全部落在区间内。此件可作为一级品入库。`
**总分 < 60 时**在文案前加一行：`本件判为废品，需回炉重铸。`（`--c-iron` 色）

## 5. 与已出设计稿的数值对账（**验收硬指标**）

规则引擎对以下输入必须输出以下结果 —— **逐位一致，不许"接近"**。

**输入**（= 画稿 S03 那一屏的状态）：
`sandbox_8`（阀体，H₀ = 6.2 %）、`T = 1380 ℃`、`V = 15.0 kg/s`、`H = 6.2 %`

**中间量与输出**：

| 项 | 计算 | 结果 | 画稿值 | 一致 |
|---|---|---|---|---|
| 造型完整度 | `100 − min(45, (1400−1380)×0.60)` = `100 − 12` | **88** | 88 | ✅ |
| 气孔控制 | `100 − min(70, (6.2−5.0)×36) − min(25, (1395−1380)×0.20)` = `100 − 43.2 − 3.0` | **53.8** → 显示 54 | 54 | ✅ |
| 铁水利用率 | `100 − min(30, (1400−1380)×1.20)` = `100 − 24` | **76** | 76 | ✅ |
| 总分 | `0.40×88 + 0.40×53.8 + 0.20×76` = `35.2 + 21.52 + 15.2` | **71.92** → 显示 72 | 72 | ✅ |
| 温度徽标 | `1380 < 1400` | 偏低 · 需升温 | 偏低 · 需升温 | ✅ |
| 视口注解 | `|1380 − 1412.5| = 32.5 ≥ 20` | 温差过大，铸件将产生缩孔 | 同 | ✅ |
| 建议速度注解 | 阀体窗口 | 12–18 kg/s | 12–18 kg/s | ✅ |
| 主因缺陷 | 扣分最大者 = 气孔 43.2（次之 冷隔 12、利用率 24） | 气孔 | 气孔 | ✅ |
| 预估值 | 89.2 → 上取整到 5 | **90** | 「90 分以上」 | ✅ |

> **九个字段全部对上。** 这意味着规则引擎与已经导出、已经展示过的设计稿**互相验证**：
> 画稿不是随手画的，规则也不是随手编的。实现时请把这张表写成单测。

## 6. 等级与工牌数据契约（对接画稿 S05）

### 6.1 等级映射

## 8. 协作车削模块（Step 3B，可在浇铸上线后实现）

### 8.1 交互流程

| 步骤 | 交互 |
|---|---|
| ① 配对 | 「双人协作模式 · 已连接 x/2」（画稿 S04）。**单人可开**：允许单人同时控制两个参数，但**不计团队协作分** |
| ② 车削 | 两个滑杆实时控制：**你 → 进给量 f**、**队友 → 主轴转速 n**（画稿 S04 分工，勿颠倒）。计时从第一次调整参数开始 |
| ③ 结算 | 质量分 + 用时 + 团队协作分 + 排行榜 |

- **参数**：主轴转速 `n ∈ [200, 1200] r/min`（步长 10）；进给量 `f ∈ [0.10, 0.80] mm/r`（步长 0.02）。
  画稿 S04 初值：`n = 620`、`f = 0.32`。
- **工件**：塔轮（6 级台阶），材料 HT200。理想窗口（精车台阶）：`n ∈ [560, 760]`、`f ∈ [0.20, 0.40]`。
- **「正在录制 · 可回放出品过程」**（画稿 S04 原文）：记录参数时间线，结算页可回放 —— 这是"可解释"的第二层证据。

### 8.2 车削评分

| 子项 | 权重 | 参数依赖 | 扣分规则 |
|---|---|---|---|
| **表面质量** | 45 % | n、f | `n` 低于 560 → 积屑瘤，系数 0.35 /(r/min)，上限 40；`n` 高于 760 → 刀具磨损与颤振，系数 0.30，上限 30；`f` 高于 0.40 → 刀痕粗，系数 120 /(mm/r)，上限 45 |
| **尺寸精度** | 35 % | n×f 的乘积（切削力） | `n×f` 高于 304（=760×0.40）→ 让刀、尺寸超差，系数 0.35 /(r/min·mm/r)，上限 35；低于 112 → 让刀不足/让刀纹，系数 0.20，上限 25 |
| **用时** | 20 % | 计时 | `用时得分 = clamp(Math.round(50 / t × 100), 0, 100)`，`t` 为秒数（**50 s 对应赵国友的 50 分钟**，是设计上的呼应，不要改） |

**团队协作分**（0–100，**不计入质量分**，单独展示、用于排行榜并列时的比较）：

```
协作分 = 100 − 时间差惩罚 − 匹配偏差惩罚
时间差惩罚 = min(30, 两人调整参数的累计时间差(s) × 2)
匹配偏差惩罚 = min(40, |f 实际 − f 理想中值| / (f 理想带宽/2) × 20 + |n 实际 − n 理想中值| / (n 理想带宽/2) × 20)
```

### 8.3 排行榜

- **排序**：先按质量分降序，同分按用时升序。
- **入榜门槛**：质量分 **≥ 60**，且用时 ≥ 10 s（**防挂机刷分**：低于 10 s 视为异常，不入榜）。
- **本局高亮**：画稿 S04 的「2 你与队友（本局）」用 `--c-iron` 描边。
- **历史纪录**：`00:50` 为固定基准（赵国友 50 分钟），不随玩家变动；「组内最佳」取本地最好成绩。

## 10. 边界情况与异常处理

| # | 情况 | 处理 |
|---|---|---|
| E1 | 滑杆拉到极值（如 T=1520、V=24、H=1.5） | 每条扣分被自身上限截断；子项最低 0、总分最低 0，**不出现负分** |
| E2 | 三个参数全部落在理想区间 | 三项全 100，总分 100，显示特别徽标「炉火纯青」；文案见 §4.3 |
| E3 | 参数为非法值（`NaN` / `Infinity` / 越界） | 引擎入口先 `clamp` + `Number.isFinite` 校验，回落该参数默认值（T=1420、V=15、H=3.5）；**任何情况下不得把 NaN 传到 UI** |
| E4 | 未做任何调整直接浇注（`sandbox_8` 初始态） | 合法，输出 §5 的 72 分；不报错、不给提示性拦截 |
| E5 | 同一参数在多条规则上触发（如 V>18 同时触发 冲砂 / 卷气 / 飞溅） | **允许**（分属不同子项）；但**同一子项内同一参数只取最大一条**（§4.2 纪律 1） |
| E6 | 一次浇注产生 0 条扣分但有 1 个参数偏离区间 | 不可能：偏离必触发至少一条规则（窗口表与规则表一一对应，实现时请断言） |
| E7 | 点击已消耗砂箱 | 无响应；不改变状态；保持 `cursor: not-allowed` |
| E8 | 射线未命中砂箱 | 无响应（§2 步骤①"无副作用"） |
| E9 | 切路由 / 刷新页面 | 本局参数清零回到步骤①；**已消耗砂箱与馆藏进度保留**（`sessionStorage` / `localStorage`） |
| E10 | 第 4 步开箱动画中切走标签页 | 用 `visibilitychange` 暂停动画计时，回来继续；不跳步、不结算 |
| E11 | 重复「调整参数重试」 | 允许，不限次数；`H₀` 不变（视作重造砂型）；**每次重试不消耗砂箱** |
| E12 | 12 只砂箱全部消耗 | 步骤①显示「砂型已用尽 · 重新制型」按钮；点击重置 12 只为未消耗，**馆藏进度不清** |
| E13 | 车削双人中一方掉线 | 该参数冻结在最后值，提示「队友已断开 · 可单人继续」，协作分归零，质量分照常计 |
| E14 | 车削用时 < 10 s 或 > 600 s | < 10 s 不入排行榜（视为异常）；> 600 s 强制结算（防止长时间占用展厅设备） |
| E15 | 显示取整导致的"看起来不对"（子项 54 + 54 + 76 ≠ 总分） | **这是预期行为**：显示值四舍五入、总分用未取整值加权。UI 上总分与子项各自独立取整，不做"凑数"修正 |
| E16 | 用户反复快速点击主按钮 | 主按钮点击后立即 `disabled`，避免重复触发动画与重复写存储 |
| E17 | 无扣分时的建议文案 | 走 §4.3 的"无扣分"分支，不生成"可提升至 100 分以上"这种无意义建议 |
| E18 | `localStorage` 不可用（隐私模式） | try/catch 降级为纯内存；馆藏进度提示「本次记录不会保存」 |

## 12. 实现约束与冻结事项

**建议文件结构**（不强制命名，但要求"规则"与"页面"分离）：

```
app/src/features/casting/
├── casting-data.js   ← §3 的砂箱表 / 铸件表 / §4.2 系数矩阵（纯数据）
├── casting.js        ← 评分引擎（纯函数：params → {total, subs, defects, diagnosis, badge}）
└── turning.js        ← 车削评分引擎（Step 3B）
app/src/pages/
├── cast.js           ← 亲手浇铸（#/cast）
└── turn.js           ← 协作车削（#/turn）
```

**必须遵守**：

1. **评分引擎必须是纯函数**：`score(params) → result`，无 DOM、无存储、无随机、无时间依赖。
   > 这是"可复现、可解释"能成立的前提，也是 T1 能被单测的前提。
2. **零随机**：不得使用 `Math.random()`。所有"变化"来自 §3.2 的静态表。
3. **`clamp` 与 `isFinite` 在引擎入口统一做**，不散落在 UI 层。
4. **数字格式**：`T` 整数、`H` 一位小数、`V` 一位小数、分数整数；统一用 `Intl.NumberFormat('zh-CN')` 或手写格式化函数，不要在模板字符串里散写 `toFixed`。
5. **Token 不动**：主按钮 `--c-iron`、面板 `--c-surface`、分数用 `--fs-display` 尺寸阶。橙色仍只用于：主按钮 / 当前选中砂箱 / 关键数值 / 进度条。
6. **允许改动 / 不允许改动的边界**：
   - **允许新增**：`app/src/features/casting/` 全部、`app/src/pages/cast.js`、`app/src/museum/scenes/cast-scene.js`
   - **允许最小改动**：`router.js`（**只新增**两条路由，不改既有行为）、`layout.css`（新增页面样式）、
     导航项「互动体验」的 `href`（`#` → `#/cast`）
   - **允许受控改动**：`museum/viewport.js` 只为把场景构造函数**参数化**（见第 9 条）；`hall.js` 若需加射线逻辑
   - **不允许改动**：`tokens.css`、`museum/scenes/workshop.js`、`museum/exhibits/*`、`museum/scenes/environment.js`、`museum/scenes/textures.js`、`museum/scenes/merge.js`
   - **不允许改变**：Step 2 建立的 `userData.sandboxNames` 拾取约定（`sandbox_0…11`）
7. **`prefers-reduced-motion`**：所有动画（开箱、分数揭示、滑杆过渡）需降级为静态切换。
8. **无新增运行时依赖**。若确实需要，先问设计方。
9. **三维视口怎么复用（重要，别自己造一套）**：
   现状 `museum/viewport.js` 的 `mountViewport(host)` 内部**写死**了 `buildWorkshop()`。
   `#/cast` 需要自己的场景与机位，但**不要把 viewport.js 复制一份**。最小改法是把它参数化：

   ```js
   // viewport.js —— 默认值保持原样，Step 1/2 行为零变化
   export function mountViewport(host, {
     buildScene = buildWorkshop,          // ← 新增，默认为现状
     cameraPos  = [16, 10, 23],           // ← 新增，默认为现状
     target     = [-3, 6.5, -5],          // ← 新增，默认为现状
     debugKey   = '__hall',               // ← 新增，默认为现状
   } = {}) { /* 其余逻辑不动 */ }
   ```

   然后新增 `app/src/museum/scenes/cast-scene.js`：浇铸小场景（12 只砂箱 + 浇包 + 冲天炉剪影 + 地面油渍），
   **直接复用 `museum/exhibits/sandboxes.js` 的 `buildSandboxes()`** —— 它已经是 `InstancedMesh`（3 个 draw call）
   且带 `userData.sandboxNames[]`，这**正是 Step 2 预留拾取约定的兑现点**，不要另写一套砂箱。
   拾取用 `Raycaster` 命中 → 读 `instanceId` → 查 `userData.sandboxNames[instanceId]`。
   `#/cast` 用 `debugKey: '__cast'`，性能读数走 `__cast.info()`。
10. **与 Step 2B（车床细节补强）的关系**：两者**文件不重叠**，可分别进行；
   唯一的交汇点是 `museum/viewport.js`（2B 加剪影钩子、本步加场景参数化）——
   若两轮在同一次会话里做，请把 `viewport.js` 的改动**合并成一次编辑**，不要分两次覆盖。

1. **E3「越界」的语义**：§10 E3 原文可两种读法。实现取「非有限值（NaN/Infinity）→ 回落默认值；有限但越界 → **钳到量程端点**」，依据是 §12 纪律 3「clamp 与 isFinite 在引擎入口统一做」要求两个操作都有意义。如需「越界也回落默认」，改 `casting.js` 的 `sane()` 一处即可。
2. **已消耗砂箱的「视觉压暗」**：InstancedMesh 无法逐实例设 opacity，且 `museum/exhibits/sandboxes.js` 冻结不改 → 用逐实例颜色压暗（约 1/3 亮度）+ `cursor: not-allowed`，语义一致。
3. **「存为我的工牌」**：已按 §6.2 写入 localStorage（no 自增 / castScore 取历史最高 / rank / unlocked n/12），但**暂不跳 `#/vault`**——数字工牌页属 Step 4，现路由会回落首页造成困惑；按钮就地反馈「已存 ✓」。
4. **`__cast.setStep(n)` 调试驱动**：走真实代码路径（真选箱、真评分引擎、真开箱动画）。其中 `setStep(4)` 为同步直落评分——无头验收环境 rAF 几乎不自主跳帧，动画与计数类表现以真机为准。**勘误（2026-09-15 晚）**：初版把"开箱动画未推进"归因于该 rAF 限制，属误判；真实原因是 `sceneRef` 为 null（P0 接线断裂），动画从未启动。修复后有头实测动画 2.0s 正常播放。
5. **开箱动画计时**：帧差推进、单帧上限 50ms。高帧率真机 = 2.0s 实长；极端掉帧时按帧数推进而非墙钟——**E10（隐藏标签页暂停、回来续播）语义优先于时长精度**。
6. **湿度滑杆「左湿右干」**：用 CSS `direction: rtl` 实现视觉反向，数值语义不变。
7. **初始参数**：T 默认 1380、V=铸件窗口中值（步长 0.5 取整）、H=该箱 H₀ —— 使 E4（sandbox_8 未调整直接浇注 = 72 分）精确成立。
