## 2. 为什么改

### A. 车床有一处可见瑕疵：13% 的屏幕框埋在砂箱阵列剪影里
现状 `(6.5, −6.6)`：屏幕框 `[911,581,1026,659]` = **114 × 78 px**，其中与砂箱阵列屏幕框
`[753,645,994,781]` 相交 **83 × 14 px**，占车床屏幕框 **13%** —— 被盖住的正是**车床的腿与底座**。
阵列在车前 3.9m，机器读起来"站在砂模堆里"。

**同一个排布里往前 1.4m 就能归零**（实测候选表）：

| 落位 | rotY | 屏幕宽 | 被阵列覆盖 |
|---|---|---|---|
| `(6.5, −6.6)` 现状 | 0° | 114 px | **13.0 %** |
| `(9.4, −7.6)` **定稿** | 0° | **121 px** | **0 %** |
| `(8.8, −8.0)` | 10° | 127 px | 2.1 % |

选 `(9.4, −7.6)`：遮挡归零、屏宽 +7px、`rotY` 保持 0°（不动你已定的朝向理由）。
落位校验：包箱 x 7.62–11.18（距导向线 x=11.5 有 0.32m）、z −8.32 – −6.89
（距警示线后沿 z=−3.0 有 3.89m、距阵列后沿 4.88m），四柱均在 11m 开外。

### B. 工具车不能回 `(13.0, −2.6)` —— 前提已经不成立
R4 给的那个位子，是**为"车床在 (15.5, −4.8)"选的**（当时它落在砂箱阵列与车床之间的空档）。
现在车床在 `(9.4, −7.6)`，两点相距 **5.5m 以上** —— 参照物离开参照对象 5 米，
近观时它就不属于这台机器了。**参照物的第一属性是"贴着参照对象"，不是"屏幕大"。**

同时说清一件事：**默认机位下工具车只有 42×38px，是几何必然，不是错误。**
车床在新位置屏幕高 78px，工具车高 0.92m 是车床 1.86m 的一半，同深度下只能是 ~40px。
**但在 `cart` 近观预设里它是 `[1126,463,1376,661]` = 250 × 198 px，完全读得清**
（抽屉分缝、把手、脚轮都在）。所以可读性判据挂在**近观预设**上，不挂在默认机位。

**做法**：工具车继续贴在车床端头外侧 **0.45m**（现状 0.43m 已满足），随车床新落位一起挪；
`rotY` 与车床一致（都是 0°）。**不要**为了把它在默认机位里变大而挪到近处。

### C. 三条阈值是"照实测反推"的，要按原则重立
本项目在 §10.4 已经立过规矩：**阈值必须由原则推导，不许把阈值改成能过**。本轮出现三处反例：

| 条目 | 现在的写法 | 问题 |
|---|---|---|
| `W4.pos` | `(6.5, −6.6)±0.1` | 数值本身随排布定，可以；但它是**先改代码再改判据**，需在本轮补上"为什么是这个位置"的原则 |
| `W5.band` | `[880, 550, 1060, 690]`，注释写"2C-R5 实测 [911,581,1026,659] ±30px" | **自指**：带子是从测量值反推的，不构成判据 |
| `W8.hRatio` | `0.40–0.62`（注释："R5 起读数自然偏大"） | 与 §10.7-B 定下的 `0.38–0.58` 不符，且理由是"我现在的读数是这么大" |

**要求**：`checks` 里每一条 `threshold` 都必须能回答"依据是什么"，**不许出现"实测值 ±N"这种写法**。
具体改成：
- 删掉 `W5.band`，换成两条有原则的：`W5.cover`（车床屏幕框被砂箱阵列覆盖 ≤ 5% —— 机器不得埋进阵列剪影）、
  `W5.presence`（车床屏幕宽 ≥ 0.45 × 砂箱阵列屏幕宽 —— 三件主展品里车床不得小于阵列的一半，
  这是"车床像玩具"那次的直接教训）。
- `W8.hRatio` 回到 **`0.38–0.58`**，依据写清：世界高比 0.92/1.86 = 0.494，屏幕比受景深与包箱纵深影响，
  取 ±0.10 只做**量级粗筛**（防"误随车床 ×1.4"冲到 ≈0.68）。

### D. 代码注释不许虚构"设计方意见"
`lathe.js` / `toolcart.js` / `hall.js` 的文件头多处写"按设计方意见""A/B 两案由设计方选定"，
但 `spec/` 里没有对应文件、也没有章节号 —— 这类归属**无法追溯**，正是本项目反复出现的
"文档与代码不一致"的来源。

**要求**：所有设计方裁定必须写成 `见 SCENE-LAYOUT-FIX-SPEC.md §10.x` 的形式。
没有章节支撑的，改成"实现方判断（未走规格）"并**不要再声称是设计方意见**。
本轮之后新增/改动的注释一律照此办理。

## 3. 做什么（四组）

### ① 车床落位微调
```js
const POS = { x: 9.4, z: -7.6 };   // 2C-R5-FIX（§10.9-A）：同排布内前移右移，阵列遮挡 13% → 0%
const ROT_Y = 0;                    // 不变（操作面正对入场）
const SCALE = { x: 1.4, y: 1.4, z: 1.4 };   // 不变
```
- **必须同步 `group.userData.displayScale`**（`layout()` 的 `axisY` 读它）。
- 文件头注释：把"落位 (6.5,−6.6)"改成新值，并把理由写成 §10.9-A 的引用。

### ② 工具车：保持相邻，随车床走
- 位置：车床包箱 **+x 端外侧 0.45m**，`z = 车床 z + 0.35`，`rotY = 0`（与车床一致）。
- 1:1 尺度、几何、材质、`userData.height = 0.92` **一律不动**。
- 文件头注释：删掉"回到 §10.7-A 落位"这类表述，改为"贴在车床端头外侧（§10.9-B）"。

### ③ `layout()` 判据
| id | 阈值 | 依据 |
|---|---|---|
| `W4.pos` | `(9.4, −7.6) ± 0.1` | §10.9-A 实测寻优 |
| `W4.rotY` | `0° ± 0.5` | 操作面正对入场，入场即读到完整侧面 |
| `W5.cover` | 车床屏幕框 ∩ 砂箱阵列屏幕框 ≤ **0.05** | 机器不得埋进阵列剪影（现状 0.13） |
| `W5.presence` | 车床屏幕宽 ≥ **0.45** × 砂箱阵列屏幕宽（实测 121/241 = 0.50） | "车床像玩具"教训：三件主展品不得差一个量级 |
| `W5.right` / `W5.bottom` | 不变（≤1380 / ≤820） | 画幅留白 |
| `W5.zoneGap` / `W5.arrayGap` / `W5.guideGap` | 不变 | 通道与不压线 |
| `W8.near` | 工具车包箱到车床包箱净距 **≤ 1.5 m**（实测 0.43m） | 参照物必须贴着参照对象 |
| `W8.readable` | `cart` 预设下工具车屏幕高 **≥ 140 px**（实测 198px） | 近观时参照物要看得清 |
| `W8.hRatio` | **0.38 – 0.58**（回到 §10.7-B） | 世界高比 0.494，屏幕比受景深影响，±0.10 粗筛 |
- 删掉 `W5.band`（自指带子）。`W9.map*` 三条保留。
- `checks` 条目数会变，`V8.checks` 的 `needPrefix` 记得同步。

### ④ 注释归属修正 + 记录两个已确认的决定

## 7. 环境坑（本项目已踩过，别再踩）

- `Bash` 只有被阉割的 PortableGit（没有 `ls`/`head`/`find`/`dirname`），**不要用管道**；用 Glob / Read。
- 无头 Edge 的 `--screenshot` 静默失效，必须走 CDP；连续启动会抢 `--user-data-dir`，**串行跑，失败重跑一次**。
- three 0.160 没有 `Scene.environmentIntensity`，环境强度是逐材质 `envMapIntensity`。
- 改 `group.scale` 后必须同步 `userData.displayScale`，否则 `layout()` 的 `axisY` 报错值。
- `HUD / 小地图 / 热点药丸` 是 **DOM 悬浮层**，屏幕框判据必须把 `getBoundingClientRect()` 一起纳入。
- **本轮的坑**：屏幕框判据要能区分"**盒子相交**"与"**真的被挡住**" —— 车床被砂箱盖住 13% 那处，
  是因为阵列在前、车床在后；换个位置盒子就不相交了，所以 `W5.cover` 用**盒子相交比例**做代理是对的，
  但阈值要按"视觉上能否看出被挡"来定（≤5%）。
