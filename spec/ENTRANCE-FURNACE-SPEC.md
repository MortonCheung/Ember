## §0 为什么换方向

用户原话：「序厅的建模主题方向这个不太好做，现在一看根本不知道是啥，要么换个方式吧。」

三版失败同一个原因，也是本项目第 5 / 6 次同类失败：**用文字描述三维形态 → 实现方忠实执行 → 得到"参数正确但看不出是什么"的东西**。

所以本轮换的不是形态参数，是**方法**：

| | 旧（作废） | 新（本文件） |
|---|---|---|
| 主体 | 一件抽象雕塑 | 一个空间（炉壁 + 炉口 + 铁水沟） |
| 形态来源 | 文字描述的连续曲面 | **房间已有坐标 + 一组开口尺寸** |
| 观众动作 | 看一件东西 | **站在炉前** |
| 一眼可命名性 | 靠抽象形态猜 → 被读成管子 / 象鼻 / 钩子 | 由"发光洞口 + 流到你脚边的铁水"直接给出 |
| 形态风险 | 高（无参照物） | 极低（全部是盒体 / 放样 / 一个开口） |

**新方向一句话**（⚠️ **这是给实现方的设计指令，不是页面文案 —— 不要把这句话写进页面**，页面文案一律以 §7 表为准）：序厅不做雕塑，做**一座炉子**。46 m 宽、18 m 高的炉壁占满后墙，中央开出 12.0 × 7.5 m 的**拱顶炉口**；炉口不是贴片 —— 后面是 **5 m 深的炉膛**，炉床是一汪发光铁水；一条**铁水沟**从炉口斜下、穿过展厅地面，在观众脚前汇成**熔池**。炉口的光在**缓慢呼吸** —— 这就是「炉火不灭」。

**"最平的墙面发光矩形"这件事，由三样东西补掉**：① 炉膛给你的纵深；② 铁水沟从远墙一直指向你脚下（最强纵深线索）；③ 前景护炉钢构，在观众与炉壁之间插进一层结构。

## §2 几何（全部世界坐标，单位 m）

### §2.1 炉壁（替换后墙）—— 一个真的开口

```js
const S = new THREE.Shape();
S.moveTo(-23, 0); S.lineTo(23, 0); S.lineTo(23, 18); S.lineTo(-23, 18); S.closePath();

const hole = new THREE.Path();
hole.moveTo(-6, 1.2); hole.lineTo(6, 1.2); hole.lineTo(6, 5.4);
hole.absellipse(0, 5.4, 6, 3.3, 0, Math.PI, false);   // 半椭圆拱顶：由 (6,5.4) 到 (-6,5.4)，冠顶 y = 8.7
hole.closePath();
S.holes.push(hole);

const wallGeo = new THREE.ExtrudeGeometry(S, { depth: 0.6, bevelEnabled: false });
const wall = new THREE.Mesh(wallGeo, new THREE.MeshStandardMaterial({
  color: 0x14171C, roughness: 0.9, metalness: 0,
}));
wall.position.set(0, 0, -14.6);      // 前表面落在 z = -14.0 —— 与原后墙同一面
```

- **炉口净开口**：宽 12.0（x −6…+6）、高 7.5（y 1.2…8.7）；起拱线 y = 5.4；拱顶横半径 6.0 / 竖半径 3.3。**必须是拱顶，不是矩形** —— 矩形开口会被读成"卷帘门 / 屏幕"，这正是上一版失败词集里的一员。
- **墙厚 0.6**（z −14.6…−14.0）。开口的侧壁就是"炉口唇口"，**不需要额外部件**（上一版就是靠额外部件糊，结果糊没了）。
- 三角面 ≈ 300（端面 + 开口侧壁），**单 mesh / 单 draw call**。

### §2.2 炉膛（凹腔）—— 纵深从哪来

```js
const cavity = new THREE.Mesh(
  new THREE.BoxGeometry(12, 10.2, 5.0),
  new THREE.MeshStandardMaterial({
    color: 0x1A0E08, roughness: 0.85, metalness: 0.05, side: THREE.BackSide,
  }));
cavity.position.set(0, 6.3, -17.1);   // x −6…6，y 1.2…11.4，z −19.6…−14.6
```

- **净深 5.0 m**（墙背面 −14.6 → 腔底 −19.6）。**这是"不是贴片"的唯一凭据，也是 E1d 判据。**
- `side: BackSide` → 只渲染朝观众的内表面；1 mesh / 12 tri。
- 腔体前缘比拱顶高（顶到 y = 11.4），透过拱口能看到腔顶 —— 这是对的，不做修补。

### §2.8 飘火（粒子）

```js
const N = 180;
const rnd = (i) => { const s = Math.sin(i * 12.9898) * 43758.5453; return s - Math.floor(s); };  // 禁 Math.random
```

- 出生盒：`x ∈ ±7`、`y ∈ 1.2…10`、`z ∈ -13.6…+3`（覆盖炉口与铁水沟前段）。
- `THREE.Points` + `PointsMaterial({ size: 0.14, sizeAttenuation: true, color: 0xFFB86B, transparent: true, opacity: 0.85, depthWrite: false, blending: THREE.AdditiveBlending })`。
- **不加贴图**：在 default 机位（34 m 距）0.14 m 的点约 2–3 px，方形点在此尺度下即读作火星；加 sprite 会破"贴图 0 增量"。
- 运动（写在 `update(t)` 里，**逐粒子解析式，不做逐帧积分**）：
  - 上升：`y = 1.2 + ((y0 + s_i · t) mod 9.8)`，`s_i ∈ 0.25…0.9`
  - 横摆：`x = x0 + 0.25 · sin(t · 0.6 + p_i)`、`z = z0 + 0.15 · sin(t · 0.45 + q_i)`
  - `s_i / p_i / q_i` 全部由 `rnd(i)` / `rnd(i + 1000)` / `rnd(i + 2000)` 得到。

## §4 动（本场景第一次有动画）

原实现 `update() {}` 注释写的是"静态场景：无逐帧动画（凝固的瞬间）"。**本轮取消该约束** —— 序厅必须有"活着"的证据，否则它就是一张贴图。

```js
update(t) {
  const k = 1 + 0.06 * Math.sin(t * 0.9);                       // 周期 ≈ 7.0 s，幅度 ±6%
  core.intensity = 6.0 * k;                                     // 炉膛内芯呼吸
  hearthOuter.material.color.copy(C_HEARTH).multiplyScalar(k);   // 炉床随呼吸
  embers.material.opacity = 0.85 * (1 + 0.08 * Math.sin(t * 0.9 + 0.6));
  // + §2.8 的逐粒子位置
}
```

- **周期必须是慢的（≈7 s）**：快闪读作故障指示灯，慢呼吸读作炉火。
- **除以上三项外不得有第四处动画**：不加雾、不加 camera shake、不加后处理、不做自动巡航。
