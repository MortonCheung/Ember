## 2. 为什么改

### 问题一：车床被改成了非等比放大，已不是 C620-1
现在是 `SCALE = (1.6, 1.3, 1.3)` → 落地 4.05 × 1.33 × 1.73 m。后果：
- **主轴中心高被拉到 1.287 m**（真实 C620-1 为 0.2 m，超 6.4 倍）；
- 长宽比从真实的 2.41 变成 3.05 —— 这台机器读起来是 CW6163/CW6180 那种 4 米大车床，**不是登在第三套人民币 2 元券上那台**；
- C620-1 是全篇唯一有具体型号 + 具体史实的展品（1955 沈阳第一机床厂、赵国友把加工时间从 4 小时压到 50 分钟），尺度失真会直接削弱它的说服力。

你在文件头写的理由（"等比放大到 2m 高会失真，车床比人还高不像话"）**方向是对的，但结论要修正**：场景里**没有任何人形参照物**，观众无从判断"比人高"；他们真正能判断的是 **"车床 : 单只砂箱"** 和 **"车床 : 工具车"** 这两组关系。所以只要这两组关系自洽，机器多大都成立。

### 问题二：砂箱才是"车床像玩具"的根因
- 车床原始真实尺度占地 2.53 × 1.02 = **2.58 m²**；单只砂箱 1.8 × 1.4 = **2.52 m²** —— **两者占地几乎 1:1**，这才是"玩具感"的来源；
- 12 只砂箱连成 **6.6 × 8.6 m** 的阵列，比车间里任何单件展品都大，抢走体量的是它；
- 而且 1.8 m 的砂箱配所铸的阀体 / 齿轮（几十厘米的件）本身就偏大，属"大砂箱"。

### 问题三（最要紧）：自检判据被放宽了，却仍报 `pass: true`
`viewport.js` 的 `layout()` 里，V3 的阈值与设计方规格不符：

| 判据 | 设计方规格原文 | 代码实际 |
|---|---|---|
| 屏幕框右边界 | `< 1320` | `< 1360` |
| 屏幕框底边 | `< 780` | `< 850` |
| 与立柱 (13,6) 间距 | `≥ 20px` | `≥ −15px`（负值＝**重叠**，注释却写"视为错开"） |
| 位置 | `(15, 0, −6)` | `(15, 0, −0.5)` |
| 新增项 | 规格中无 | `Math.abs(lRotY − 30) < 0.5` |

实测当前 `clearColumnPx = −10`，即**车床屏幕框与右前立柱屏幕带重叠 10 px**，`layout()` 却报 `V3: true`。阈值是设计方按屏幕投影算出来的**构图保护值**，静默放宽等于拆掉唯一的自动验收防线。

**这条本身（阈值可能过时）不算错，错在"改了却没说、还报了通过"**。本轮的解法是把阈值**按原则重新推导一次、写明依据**，并且让钩子把"阈值 + 实测值 + 通过与否"一起返回 —— 以后任何人想改阈值，都会在返回值里留下痕迹。

## 3. 做什么（六组，全部有实测目标值）

> **轴序约定（本节起全局生效）**：所有三元尺寸一律按 **世界轴序 `(x, y, z)`** 书写。
> 例：车床 `boxLocal` = (3.54, 1.86, 1.43) 表示 x 向长 3.54、y 向高 1.86、z 向宽 1.43；
> 砂箱单箱 = (1.26, 0.63, 0.98)。**语义名（长/宽/高）随物件而变，轴序不变**，避免歧义。

### ① 车床改等比：`SCALE = (1.4, 1.4, 1.4)`
```js
const SCALE = { x: 1.4, y: 1.4, z: 1.4 };   // 2C-R3：等比展陈放大，内部比例保持真实
```
| 项 | 值 |
|---|---|
| 落地尺寸（**未旋转**，轴序 x/y/z） | **3.54 / 1.86 / 1.43 m** —— x 向总长 3.54、y 向总高 1.86、z 向总宽 1.43（= 模型基准 长2.53/宽1.02/高1.33 统一 × 1.4） |
| 主轴中心高 | 0.99 × 1.4 = **1.386 m**（比例 0.743，与模型基准 0.99/1.33 一致） |
| 对真实 C620-1 的放大 | 1.47 倍（三轴同倍，**等比**） |

⚠️ **必须同步 `group.userData.displayScale = [1.4, 1.4, 1.4]`** —— `layout()` 的 `axisY` 读的是它，只改 `group.scale` 会让自检报错值。
⚠️ 同步更新文件头注释（现在写的是 R2 的差异化放大理由，已作废）。

### ② 车床落位与朝向
```js
const POS = { x: 15.5, z: -4.8 };   // 原 (15, -0.5)
const ROT_Y = 20 * Math.PI / 180;   // 原 30°
```
实测目标（默认机位 1440×900）：

| 判据 | 目标 | 现状（R2 位） |
|---|---|---|
| 屏幕框 | ≈ **[1181, 632, 1356, 755]**（175 × 123） | [1139, 671, 1331, 826] |
| 与立柱 (13,6) 屏幕带间距 | **≈ 45 px** | **−10 px**（重叠） |
| 与砂箱作业区 | ≈ 3.78 m | 3.21 m |
| 与地面导向线（x=11.5） | ≈ 2.09 m | 1.42 m |
| 旋转后 AABB | ≈ 3.84 × 1.86 × 2.56 m | 4.20 × 1.73 × 3.18 |

（保留 20° 是必要的：正面平视图看不到溜板箱与手轮，机器读不出"车床"。）

### ③ 砂箱在展厅侧缩到 0.7 —— **不动 `props/sandboxes.js`**
```js
// workshop.js，紧邻现有的 position.set(-2,0,-2) 那行
sandboxes.group.scale.setScalar(0.7);
sandboxes.group.position.set(0.55, 0, -1.1);
```
- **位置公式**：`position = 目标世界中心 (6.5,1) − scale × 模块中心 (8.5,3)`，即 `(6.5 − 5.95, 1 − 2.1) = (0.55, −1.1)`。
- **为什么走展厅侧**：`buildSandboxes()` 被 `scene/cast-scene.js` 复用，改模块常量会连带改 cast 小场景（违反"不动 cast 页"）。这与你们现有 `(−2,0,−2)` 平移是同一套做法，保持一致。

**实测结果**

| 项 | 值 |
|---|---|
| 单箱落地 | **1.26 × 0.63 × 0.98 m** |
| 阵列世界范围 | **x 4.19 – 8.81，z −2.01 – 4.01**（4.62 × 6.02 m） |
| 阵列屏幕框 | ≈ **[753, 645, 994, 781]**（241 × 136） |
| `props/sandboxes.js` | **零改动**（CENTER 8.5/3、BOX 1.8/0.9/1.4、GAP 2.4 全部保持） |

### ④ 作业区警示线四段收到新阵列外沿（外扩 1 m 的原有约定不变）

### ⑤ 新增已知尺寸参照物：**工具车**（`props/toolcart.js`）
目的是让观众有个熟悉尺寸可比，机器立刻读得出体量——这是博物馆让"小展品不显小"的标准手法。

| 项 | 值 |
|---|---|
| 世界尺度 | **1 : 1（0.92 m 高）**，⚠️ **不参与车床的 ×1.4 缩放**，必须挂在 workshop 而不是 lathe group 内 |
| 尺寸 | 0.92 高 × 1.10 长 × 0.55 宽 |
| 构成 | 柜体 `Box(1.10,0.78,0.55)@y0.39`；台面 `Box(1.16,0.05,0.60)@y0.805`（略外挑）；抽屉分缝 3 道 `Box(1.06,0.012,0.02)` @ 前面板 y 0.22/0.42/0.62；把手 ×3 `Box(0.28,0.03,0.03)`；脚轮 ×4 `CylinderGeometry(0.06,0.06,0.05,16)` rotZ @ 四角 y0.06 |
| 材质 | 与车床同族：漆面 0x4A5A52 + 亮钢 0x8B939E，合并为 **2 mesh / 2 draw call** |

### ⑥ 判据还原 + 硬化（**本轮的核心交付**）
**(a) 阈值按原则重新推导**（不是照现状反推）。设计方原值 1320/780 是从"较小车床 + 旧位置"的预测位置推出来的，现在车床是有意放大，故**按原则重推**，依据写进注释：

| 判据 | 新阈值 | 依据 |
|---|---|---|
| 屏幕框右边界 | `≤ 1380` | 距画幅右沿 ≥60 px（留小地图 / 滚动条余量） |

| **与立柱 (13,6) 屏幕带间距** | **`≥ 20 px`** | **硬判据，本轮不许放宽**（负值即重叠，不允许） |
| 与砂箱作业区 | `≥ 2.0 m` | 操作空间 |
| 与地面导向线 | `≥ 1.0 m` | 不压线 |
| 落位 / 朝向 | `(15.5, 0, −4.8)±0.1`、`rotY = 20°±0.5` | 由屏幕投影实测选定 |

**(b) `layout()` 追加 `checks` 数组**，把每条判据的**阈值、实测值、结果**一起返回（`pass` 布尔保留不动，向后兼容）：
```js
checks: [
  { id: 'W5.right',  name: '屏幕框右边界', threshold: '<=1380', value: 1356, ok: true },
```

**(c) 车床判据拆成两组**：`boxAABB`（旋转后，用于屏幕框）与 `boxLocal`（未旋转 = 模型基准 × scale，用于验等比）。现在只返回旋转后的 AABB，无法验"三轴等比"。
